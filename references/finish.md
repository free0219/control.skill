# 完成与清理
默认关闭。仅用户主动明确提出清理时进入本流程，授权只在本次指定范围内有效。测试、完成任务或项目完成均不触发清理，也不自动运行清理预览。仅请求清理缓存时只检查和处理指定缓存，不据此完成项目、归档仓库或删除项目；下面完整结束流程仅适用于用户明确要求“项目完成并清理”。不重复索要已明确给出的相同授权。
1. 检查交付内容可用；更新deliverables、completed和状态并提交。以用户时区建立唯一control-final-YYYYMMDD-HHMMSS标记，不移动旧标记。
2. 启用云端推送时执行sync及verify-remote（不要求云端执行）。最终文件实际保存在仓库内，不以临时链接代替。LFS需另行验证对象可下载，当前脚本拒绝LFS指针，不冒称已备份。
3. 在仓库外建立最终交付目录，复制deliverables，逐文件SHA256比较并检查打开/渲染。附仓库和最终标记说明。
4. cleanup-preview通过后，验证无唯一未保存资料，再用gh/连接器归档私人仓库只读。归档失败保留本地，不假报完成。
5. 自建专用目录才可整库删除。删除前核验解析绝对路径、仓库根、配置及所有者一致，最终导出不在删除范围。所有未跟踪/忽略文件均检查用途；不明确则保留或询问。Windows用同一PowerShell的LiteralPath，不跨shell拼接。
6. 复用仓库、共享仓库、原始资料目录不整库删除；只移除可再生成缓存和已核验完整保存的冗余旧稿。
纯本地保留.git和唯一历史，仅清理可再生成文件；用户另行明确丢弃历史时说明不可恢复后按授权处理。
未同步提交、缺少导出、验证失败均不得删除恢复所需信息。脚本只预览，不删除。
GitHub保留完整历史及最终交付；不删除云端聊天/环境，不自动终止其他任务。明确恢复归档项目时可解归档继续。
报告实际释放字节、最终交付位置和历史位置；不能宣称删除原目录之外的资料。
