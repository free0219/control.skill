# 云端推送与云端执行

## 云端推送：GitHub同步
用户选择“本地版本管理并启用云端推送”，授权本项目范围内的GitHub建库/复用、提交和上传，不包含Codex环境创建、发布或聊天创建。新建备份仓库默认私有；已有远端不覆盖，已有公开仓库不改为私有。公开仓库仅在用户明确指定/授权时使用，不扩大上传范围。

先检查已提供的连接器和Git认证。平台HTTPS Git代理可以提供认证，不要求GH_TOKEN/GITHUB_TOKEN存在。先执行git ls-remote origin HEAD验证读取，推送后核对远端哈希。读取成功不证明推送权限。优先受支持工具核验仓库身份和可见性；gh可用时使用gh repo view。仅必须登录的操作才请用户完成安全授权，不在聊天索取令牌。

需建库时，核验实际GitHub身份，不硬编码账号；仓库名从项目名生成，冲突加后缀。创建空私有库，不生成README/许可证；验证身份和private=true，失败后复用已有结果，不重复建库。

设置mode=cloud、remote和真实目标branch。提交前检查本轮文件归属；推送前inspect --history检查全部可达历史。脚本remote_info默认要求私有仓库并使用gh验证元数据；缺少gh认证但平台Git认证可用时，可用受支持工具完成同等元数据核验，再用原生Git定向推送及哈希核对，不绕过历史扫描或身份检查。用户明确指定的公开源库也走此受支持流程，不能伪造isPrivate或禁用脚本保护。

只推送已提交内容及项目最终标记，不强制推送、不推无关分支。branch存在时使用配置目标分支；旧配置缺失时兼容当前分支。分支与当前执行位置无关，云环境中的work分支可正常同步已配置的main。拒绝覆盖远端新增提交；先比较历史，再安全合并或保留双方修改。失败保留本地提交并明确“尚未同步”；同步完成即可报告云端推送完成。

## 本地跨设备接续
设备A结束前提交并推送；设备B先检查已有修改，再克隆或安全拉取，读取AGENTS.md、PROJECT_STATE.md和项目内技能副本。工作区干净且无分叉时才快进；分叉或未提交修改先保留，不重置覆盖。完成后验证、提交、推送并核对。无需Codex云环境，也无需源设备在线。

DOCX等二进制文档有冲突时保留双方文件，不自动文本合并。默认个人串行切换，避免多设备/云端同时修改同一份主稿，不增加多人锁、强制PR或后台监听。

## 云端执行：Codex云环境（独立可选）
仅在用户明确要求/同意后启用cloud_execution.enabled；当前对话已有授权时直接沿用。复用现有隔离checkout，不主动创建Git worktree。云端执行只解决运行工具和完成任务，不替代Git历史或GitHub同步，也不自动获取本地未推送修改或完整聊天上下文。

先发现当前宿主的环境状态、配置、发布及聊天工具，读取适用技能。复用匹配项目的环境；用户已进入可用环境时直接验证，不额外创建重复环境。配置仓库、必要依赖和服务启动步骤，执行实际任务所需检查。保留源文件和用户改动；Word需验证读取、保存、转换、字体和预览，字体替代必须说明，不能声称原机排版完全一致。

按宿主支持流程保存可复用配置；保存不等于执行、应用或发布。支持代理发布且已授权时执行；宿主要求用户审阅/发布时，只交给用户完成不可代办的最小操作。不得猜内部接口或制造环境ID/链接。当前环境验证成功不证明发布成功；发布成功不证明新任务恢复成功。无发布能力时只报告已完成的当前实例验证及待办，不阻塞GitHub同步。

接续聊天仅在用户需要且宿主支持时创建/复用，不作为云端推送或每次云端执行的必需条件。记录真实返回的环境/聊天标识、仓库、分支、工具限制和验证结果；未取得的留空。请求超时先核查已有结果，不重复创建。

## 验收与边界
分别报告本地已保存、GitHub已同步、当前实例执行已验证、配置已保存、环境已发布、新任务恢复已验证。云端执行未启用时不列为欠缺项。工具、凭据或字体受阻只影响依赖该能力的步骤，不扩大为整个版本控制失败。不复制本机凭据、个人配置、全局记忆或完整聊天。
