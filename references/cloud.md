# 云端执行
用户选择“本地版本管理并启用云端推送”即授权本项目范围内的私有建库、上传、创建/配置/发布项目云端环境及接续聊天。先明确必要文件范围，已有授权不重复索取。登录、GitHub连接授权等必须由用户本人完成的步骤才交给用户；不得把全部建环境步骤作为默认用户操作。核验当前GitHub身份，不硬编码某个账号。
优先现有连接器；不支持建库时用GitHub CLI。检查gh --version和gh auth status。缺失通过官方渠道安装，登录由用户完成浏览器交互；不输出令牌。连接器登录不等于CLI登录。
仓库名从项目名生成英文/拼音短名，查询重名加数字后缀。gh repo create OWNER/NAME --private创建空库，不生成README/许可证等。读取元数据验证private=true和所有者。已有origin不覆盖。失败重试复用已创建仓库，不重复建库。
设置配置mode=cloud及remote，checkpoint后运行sync。正常推送当前分支和control-final标记，不推无关分支，不强制推送。

## 云端交接
源设备先将 `.agents/skills/control`、AGENTS.md、PROJECT_STATE.md及配置提交推送。个人技能目录不会自动同步到云端；仓库内技能可以供云端任务使用。新设备只需登录同一账号并进入本项目云端环境/聊天，无需另外安装control技能，也无需保持源设备开机。
启用后将仓库URL、分支、项目名称、主稿及接续入口写入项目Markdown和配置并同步。同目录新对话直接读这些文件；换电脑优先打开同账号下已创建的该项目云端聊天，说“继续这个项目”。独立无上下文聊天不能保证从“这个项目”识别目标，应先从已有项目/聊天找到记录；仅存在多个同名候选时询问项目名称，不要求用户重贴已记录的仓库链接。
先发现当前可用的环境列举、创建/编辑/发布及聊天工具。复用已记录且关联本仓库的已发布环境；没有时自动创建以项目命名的可复用环境，关联仓库、配置必要工具、验证后发布。优先受支持的专用工具；工具缺少创建/发布能力时，从源设备使用已授权的浏览器/界面操作，先读取对应操作技能，不猜测内部接口。环境授权页交由用户本人完成。
宿主只有list_cloud_environments和create_thread时，它们只能选择已有环境并创建聊天，不能据此宣称已创建/发布项目环境。默认环境可作临时访问验证，但必须标记为临时，不能替代项目环境完成验收。工具及界面均无法完成时，保存明确待办、缺少的能力及已完成步骤，仅请求用户完成不可代办的最小步骤，不把手动配置整套环境当作正常路径。
环境发布后使用真实返回的environmentConfigId创建接续聊天，target=codexCloud，不能用普通ChatGPT对话冒充。模型/推理配置默认不传，除非用户指定。云端先只读验证；不擅自启动正在本地进行的修改工作。
交接提示包含仓库URL、分支、预期提交、项目目标、读取AGENTS/状态/技能、待做事项和检查工具。无待做任务时只验证接续后等待，不自创工作。
创建异步，使用宿主等待/读取工具确认云端读取预期版本、项目资料与规则，验证关键工具和私人仓库访问。新仓库可能需要用户补充连接权限。只有确认后报告接续成功，返回真实聊天入口及宿主要求的创建聊天指令。将真实环境ID、聊天ID和验证状态回写项目配置和Markdown；云端只读验证、本地回写完成后再接续，避免两边重复修改。交接后本地不重复执行同一工作。
请求超时或创建结果未知时，先列举现有环境/聊天核实，不盲目重复创建。受阻时告知并本地继续，保存待接续状态和下一步，不无限等待。网络重试一次仍失败则保存提交并报告，下一轮重检。

## 验收与持久记录
分别记录真实的仓库地址与分支、环境名称/ID/发布状态、接续聊天ID/入口及验证结果；未取得的值留空或标待确认，不能从预期名称推断ID。仅上传成功不等于环境就绪；仅创建聊天不等于云端已读取项目。
验收至少包括：云端读取GitHub最新分支、项目AGENTS/状态和仓库内技能；确认原始资料及主稿可读；新任务使用该项目环境可重新加载规则。后续实际修改按自动版本控制规则提交和同步，不为验证擅自改报告或清理文件。

云端读取仓库内技能副本；按任务配置依赖，不复制本机安装目录。Word必须验证实际可用文档工具/字体/预览；无法复现的本机检查保留待办。
若云端使用原生安全GitHub工具而非gh，仍须完成历史扫描、私人仓库检查、正常推送和远端哈希核对；不能绕过缺失验证。
换机优先继续原云端聊天；新任务读最新远端分支和状态记录。回本地先检查未提交修改，干净时快进更新；分叉保留两边，不强制覆盖。默认个人串行切换，不建多人锁或PR流程。
